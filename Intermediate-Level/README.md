## 📖 Overview

This level moves past static pages into **real, data-driven applications**. Projects here consume third-party APIs, manage async state, and increasingly lean on frameworks like React and Vue instead of vanilla JS. The goal is to get comfortable with the patterns you'll actually use on the job: fetching and caching data, handling loading/error states, component structure, and routing.

**Goal:** Master APIs, state management, frameworks, and build real applications
**Tech Stack:** JavaScript, REST APIs, React/Vue, LocalStorage, Advanced CSS
**Prerequisites:** Comfortable with [Beginner Level](../Beginner-Level/README.md) — DOM, events, and vanilla JS fundamentals

## 🛠️ Technologies Covered in This Level

- REST APIs — Fetch, async/await, error & loading states
- React.js, Vue.js, Angular fundamentals
- State management & client-side routing
- Tailwind CSS, Bootstrap
- Third-party API integration (weather, movies, currency, GitHub, etc.)

## 🚀 How to Run a Project Locally

Most projects here are still framework-free or use a lightweight bundler. Check each project's own README for exact steps, but the general flow is:

```bash
cd Intermediate-Level/Project-101
npm install    # if a package.json is present
npm run dev    # or open index.html directly for non-bundled projects
```

Several projects call external APIs — you may need to grab a free API key (OpenWeather, TMDb, NewsAPI, etc.) and drop it into a `.env` or config file as described in that project's README.

## 🤝 Contributing to This Level

This level has the most room to grow — only 8/100 done. Good first contributions:
- Pick up any ❌ **Not Started** project (109, 110, or propose a new one for 111+)
- Improve error handling / loading states on an existing project
- Add a proper `.env.example` where an API key is required

Fork the repo, build inside `Intermediate-Level/Project-XXX`, include a README with setup + live demo link, and open a PR. Full workflow in the [main contributing guide](../README.md#-contributing).
